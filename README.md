Проект: учёт сборки и приёмочного тестирования сервера по утверждённой спецификации.
Вход — заказ и спецификация, результат — протокол испытаний и решение о готовности
сервера к передаче. Закупки и обслуживание после передачи пока не входят в проект.

Для разработки выбраны Dart и PostgreSQL, редактор Visual Studio Code.
На КТ1 нужны описание процесса, источники и начальный проект. Полная автоматизация
относится к следующим этапам практики.

Репозиторий пока локальный. Ссылка будет добавлена после создания GitHub-репозитория.

## Запуск

Проверено с Dart SDK 3.13.5 и PostgreSQL 16.13. Внешних Dart-пакетов на КТ1 нет.

```sh
dart run bin/check.dart examples/protocol.json
dart run test/check_test.dart
dart analyze bin test
```

Код возврата: 0 — все проверки успешны, 1 — есть несоответствие или пропуск,
64 — неверный файл или входные данные. Пример полностью учебный, это не результаты
испытаний реального сервера. Программа проверяет введённый протокол, сама тесты
оборудования не запускает и не заменяет подпись ответственного за приёмку.

Начальная схема БД находится в `sql/schema.sql`. Применять к пустой учебной базе:

```sh
createdb server_checks
psql -d server_checks -v ON_ERROR_STOP=1 -f sql/schema.sql
```

Вызов PostgreSQL из Dart ещё не реализован. Он понадобится при добавлении хранения
заказов и результатов на следующем этапе; предполагается пакет `postgres`.

В `docs/process.txt` описаны границы процесса, в `docs/sources.json` — библиография
и ссылки, подтверждающие включение пяти научных публикаций в ВАК/Scopus.
Действующие стандарты учитываются по исключению из пятилетнего ограничения.
