# Образовательные программы и приоритеты роста

Программы сопоставлены с выборкой вакансий в `market.md`. Сведения просмотрены 21 ноября 2026 года. Рассматриваются содержание, длительность и входные требования; покупка обучения не требуется для выполнения практики.

## Сравнение программ

| Организация и программа | Длительность и аудитория | Содержание | Связь с вакансиями и проектом |
| --- | --- | --- | --- |
| [Яндекс Практикум — Java-разработчик](https://practicum.yandex.ru/courses/java-developer/) | Базовая программа — 10 месяцев, с нуля; расширенный тариф — 14 месяцев | Java Core, ООП и коллекции, Git, SQL/PostgreSQL, Maven, Spring, модульные и интеграционные тесты | Соответствует требованиям V01–V03 по разработке и части V05 по тестированию. Для проекта помогает перейти от CLI к сервису с БД; часть основ пересекается с уже подготовленной практикой |
| [Яндекс Практикум — Автоматизатор тестирования на Java](https://practicum.yandex.ru/qa-automation-engineer-java/) | Базовый курс — 5 месяцев; рассчитан на переход из ручного тестирования | Java, Git, API-автотесты Rest Assured, UI-проверки Selenium/Selenide, отчётность Allure и запуск в Jenkins | Напрямую связан с V04–V05. Для текущего проекта полезны тестовый фреймворк и CI; UI-раздел станет нужен только при появлении интерфейса. Сначала необходима база тест-дизайна и ручного тестирования |
| [OTUS — Системный аналитик](https://otus.ru/lessons/system-analyst-specialization/) | Специализация с нуля — 13 месяцев, онлайн | Требования и интервью, BPMN/UML/ER, документация, архитектура, REST API, SQL/NoSQL, сопровождение разработки и приёмка | Соответствует V06–V08. Поможет развить модели практики в требования для команды и согласованный контракт интеграции. Не является заменой необходимого в этих вакансиях коммерческого стажа |

Для основной траектории Java-разработки наиболее прямое соответствие имеет первая программа. Вторая — вариант специализации в качестве ПО, третья — в системном анализе. Проходить все три подряд не требуется: выбор зависит от предпочитаемой роли и самостоятельной оценки пробелов. Платный курс можно заменить самостоятельным планом с проверяемыми проектными результатами.

## Приоритеты для продолжения проекта

| Приоритет | Основание в выборке | Следующее действие | Проверяемый результат |
| --- | --- | --- | --- |
| 1. SQL и работа с реляционными данными | SQL — 5/10: V03, V04, V05, V06, V08 | На КТ4 перенести 11 сущностей в БД; отработать JOIN, ограничения, транзакции и подготовленные выражения JDBC | Схема с PK/FK/UNIQUE; один и тот же протокол из JSON и БД; тест отката при ошибке записи |
| 2. Java, контракты объектов и тестирование | Java — 5/10: V01–V05; JUnit/TestNG — 2/10: V04–V05 | Разобрать самостоятельно каждое правило; перенести автономные проверки в JUnit, добавить параметризованные тесты и изоляцию зависимостей | Воспроизводимый тестовый запуск; объяснение наследования, интерфейса и неизменяемых снимков без обращения к исходным заготовкам |
| 3. Git и автоматизация сборки | Git/GitLab — 5/10: V01, V03, V05, V09, V10; CI/CD — 4/10: V03, V05, V09, V10 | Настроить CI для javac и тестов, затем сравнительного запуска Python/Java; освоить review и исправления отдельными коммитами | Изменение, нарушающее ожидаемый протокол, приводит к красному CI; исправление возвращает зелёный результат |
| 4. Требования и проектирование интеграции | REST/API — 5/10: V01, V05–V08; BPMN и UML — по 3/10: V06–V08 | Описать API заявок и прогонов, ошибки и критерии приёмки; согласовать изменения модели с процессом | OpenAPI-описание и связь каждого сценария с операцией, сущностью и тестом |
| 5. Эксплуатация приложения | Linux/Unix — 3/10: V04, V09, V10; контейнеризация — 4/10: V02, V05, V09, V10 | Запустить приложение в Linux, настроить сбор логов и резервное копирование будущей БД; затем контейнерный запуск | Инструкция развёртывания на чистом окружении и успешная проверка восстановления резервной копии |

Последовательность начинается с данных и проверяемого поведения, затем переходит к доставке и эксплуатации. Kubernetes и распределённые брокеры встречаются в опытных вакансиях, но для текущего CLI-приложения отдельный кластер не нужен. Сначала следует подтвердить базовые навыки на работающем проекте.

Личная самооценка ещё не уточнена: план ориентируется на текущие артефакты практики. Перед включением в итоговый отчёт автор отмечает, какие действия уже умеет выполнять самостоятельно, и корректирует порядок приоритетов.
