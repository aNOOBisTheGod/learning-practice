## Запуск

Нужен **JDK 17+**, для сравнительного теста — также **Python 3.12+**. Java не использует внешние библиотеки и не загружает зависимости. Для просмотра PNG PlantUML не требуется.

Из корня распакованного комплекта либо репозитория:

```sh
sh kt3/src/java/test.sh
java -cp kt3/src/java/out practice.Main kt3/src/java/examples/data.json --run 2
java -cp kt3/src/java/out practice.Main kt3/src/java/examples/data.json --run 1
python3 scripts/check_kt3_parity.py
```

Ожидается: 44 проверки Java; для прогона 2 — `Предварительный допуск: ДА` и код 0; для прогона 1 — `Предварительный допуск: НЕТ`, причина `Тест 2: fail` и код 1. Последняя команда проверяет 150 сравнительных сценариев и ещё 7 случаев CLI. Код 1 у первого прогона — ожидаемый результат предметной проверки, а не ошибка сборки.

Для Windows PowerShell точные команды сборки и тестирования приведены в Java README. Скрипт сравнительной проверки использует `sh`; на Windows его можно запускать в Git Bash/WSL. Автономные Java-тесты запускаются и без `sh` по командам README.

## Что проверить

1. Сопоставить 11 сущностей КТ2 с классами Java и UML. Проверить видимость, типы полей, связи и кратности.
2. Проверить, что `ConfigurationRule` и `ProtocolRule` меняют поведение общей базы `AbstractAcceptanceRule`, а `ProtocolService` обращается к ним через `AcceptanceRule`.
3. Проверить коллекции, инкапсуляцию и сохранность исходных данных: изменение входного JSON после создания `DataSet` не должно менять снимок.
4. Проверить оба алгоритма, порядок причин отказа и учёт открытых дефектов прежних прогонов той же заявки.
5. Самостоятельно собрать программу по README, проверить пример и хотя бы несколько негативных случаев. Можно изменить копию JSON: удалить результат теста, открыть старый дефект, уменьшить комплектацию, нарушить ссылку.
6. Оценить читаемость и обработку ошибок. Для каждого замечания указать файл, метод/строки, воспроизведение, последствия и конкретное предложение.

## Как вернуть рецензию

Выбран вариант **рецензирования в файле**: заполни `review_form.md` и пришли его автору. Доступ на запись в репозиторий не нужен. Если реальных дефектов не найдено, перечисли выполненные проверки и их результаты; замечания выдумывать не нужно.

Для обратной рецензии пришли своё ФИО, группу, ссылку на свой репозиторий и точный коммит КТ3 либо архив исходников, UML и README. Полученные замечания и ответы автора позже войдут в итоговый `review/review.md`; исправления будут отдельными коммитами.

Токены, пароли, `.env`, доступ к аккаунту или права администратора для проверки не нужны. Если ссылка GitHub недоступна, автономный ZIP содержит всё необходимое для запуска и сравнения. Этот комплект предназначен для review и включает Python КТ2; он не является итоговым архивом КТ3 для СДО.
